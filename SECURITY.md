### Findings

[NOTE] .claude/settings.json:4-7 -- The evaluator ask rules cover only built-in edits to two files plus two flag substrings. They do not enforce most of what CLAUDE.md:102 lists as requiring human approval, and ask beats the broad allow rules in `settings.local.json` only for commands that match an ask pattern. Confidence: high.
  Attack vector: The adversary is the project's own coding agent, either reward-hacking toward a green gate or steered by injected text. (1) Subprocess writes. `.venv/bin/python -c "..."` that rewrites `tests/medium/quality_baseline.json` or `reforge/evaluate/regression_gate.py` matches the allow rule `Bash(.venv/bin/python:*)` (`.claude/settings.local.json:42`) and no ask rule. Claude Code applies Edit rules to its built-in file tools, to recognized file commands such as `sed` and `tee`, and to redirection targets. Its permission docs say they do not apply to "arbitrary subprocesses that read or write files indirectly, like a Python or Node script that opens files itself". In auto mode the outcome then rests on the allow rule or the classifier, not on a human prompt. (2) Gate-defining files with no rule, which auto and acceptEdits modes edit without a prompt: `reforge/config.py:161` (`PRIMARY_METRICS`) and `:189` (`QUALITY_CONTINUOUS_WEIGHTS`), `tests/medium/test_quality_regression.py:45,56,85,296` (`SSIM_THRESHOLD`, `TEST_WORDS`, `REGRESSION_TOLERANCE`, `strict=True`), `tests/medium/conftest.py:10-18` (flag defaults), `tests/medium/reference_output.png`, and the metric code in `reforge/evaluate/visual.py`. Setting `PRIMARY_METRICS = []` or `REGRESSION_TOLERANCE = 1.0` disables the primary-metric check and leaves every protected file untouched.
  Evidence: The ask list is at `.claude/settings.json:4-7`. CLAUDE.md:102 names `PRIMARY_METRICS`, gate thresholds, the gate's word list, `quality_baseline.json`, `reference_output.png` and `QUALITY_CONTINUOUS_WEIGHTS` as human-approval items and says the settings file "enforces part of this".
  Remediation: Move the gate-defining constants (primary metrics, tolerance, SSIM threshold, word list) into the protected `regression_gate.py` or one dedicated gate file. Add ask rules for `tests/medium/test_quality_regression.py`, `tests/medium/conftest.py`, `tests/medium/reference_output.png` and `reforge/evaluate/visual.py`. For enforcement that also covers subprocesses, enable Claude Code sandboxing with write denial on those paths, or replace the interpreter-wide allows (`Bash(.venv/bin/python:*)`, `Bash(.venv/bin/python3:*)`, `Bash(python -c *)`, `Bash(bash:*)`) with specific commands.

[NOTE] tests/medium/test_quality_regression.py:248 -- The push gate fails open. A missing baseline or reference file is re-recorded from the current output and the test passes. On a host where CUDA is not visible the test class is skipped, which pytest reports as success. Confidence: high.
  Attack vector: `.githooks/pre-push:12-16` runs only this test and blocks only on a non-zero exit. (1) Remove `tests/medium/quality_baseline.json` by a route the ask rule does not cover (previous finding), then push. Line 248 takes the "initial bootstrap" branch, saves a baseline from the current, possibly regressed, output and returns at line 257, before the OCR floor and metric checks. Line 380 does the same for `reference_output.png`. (2) Run `CUDA_VISIBLE_DEVICES= git push`. The hook inherits the environment, `torch.cuda.is_available()` is false, the `skipif` at line 208 skips both tests, and pytest exits 0. A GPU driver failure has the same silent effect.
  Evidence: Lines 248-257 (`if baseline is None or force_update:` through `return`), 380-384 and 208; `.githooks/pre-push:12-16`.
  Remediation: Fail when either reference file is missing unless `--update-baseline` or `--update-reference` was passed. Make the hook fail when CUDA is unavailable (a `torch.cuda.is_available()` check before pytest), or turn skips of this module into errors.

[NOTE] reforge/model/generator.py:1170 -- Words from user text that fail OCR are appended, with a timestamp, to `reforge/data/hard_words.json`. That file is tracked in this public repository, and this push routes more user tokens into it. Confidence: medium.
  Attack vector: A reader of the public repository. When `reforge.py --text ...` renders a private note, any single-chunk word whose OCR stays below 0.4 after two retries reaches `_record_hard_word_candidate` (generator.py:1168-1170, 1233-1239). `add_candidate` (`reforge/data/words.py:65-89`) then writes it to `_HARD_WORDS_PATH` (words.py:18). There is no opt-out. The file is committed in routine refresh commits (7a19459 "Refresh demo output and hard word watchlist", 5c18d1b), so the recorded words, names included, reach public history with the next such commit. New in this push: generator.py:1004-1017 sends every token with trailing punctuation through the retry loop, so "Smith." is now recorded as "Smith". The removed `_generate_punctuated_word` path never recorded anything.
  Evidence: generator.py:1004-1017, 1168-1170 and 1233-1239; words.py:18 and 65-89; `git ls-files reforge/data/hard_words.json` lists the file.
  Remediation: Record auto-collected candidates in a gitignored location (`experiments/output/` is already ignored) and let the triage CLI promote them from there into the tracked curated list. Alternatively, gate recording behind an env var that only test and eval entry points set, as `REFORGE_LOG_CANDIDATES` does for candidate scores.

[NOTE] .claude/settings.local.json:56 -- (Outside this run's path scope; read to evaluate `.claude/settings.json`.) This personal permission file is tracked in this public repository. Claude Code loads it from the repository root, so anyone who clones the repo and trusts the folder inherits its allow rules, including unprompted shell and interpreter execution. The file also publishes local paths. Confidence: medium.
  Attack vector: In a clone opened in Claude Code, these rules are pre-approved: `Bash(bash:*)` (line 56), `Bash(.venv/bin/python:*)` (42), `Bash(python -c *)` (8), `Bash(.venv/bin/pip install:*)` (48) and `Bash(make:*)` (12). So are `WebSearch` (60) and WebFetch for domains that host user-generated content (github.com at 34, medium.com at 62). Instructions injected into fetched content can then run as shell commands with no prompt in default or acceptEdits mode. The same applies to the owner's own sessions in those modes. Auto mode drops interpreter-wide allow rules, which narrows this, but rules such as `pip install` may stay in effect. Lines 11 and 67-68 publish `/home/peter/...` and `~/src/qwen-2.5-localreview` paths.
  Evidence: `git ls-files .claude` lists the file, and `git check-ignore` does not match it. `gh repo view` reports `isPrivate: false`. The Claude Code permission docs say `.claude/settings.local.json` "loads from the git repository root".
  Remediation: Run `git rm --cached .claude/settings.local.json` and add the file to `.gitignore`. Earlier copies stay in history, but they contain no secrets. Replace the shell-wide and interpreter-wide allows with specific commands, and keep intentionally shared rules in the tracked `.claude/settings.json`.
