[NOTE] experiments/replay_cache.py:103 -- Generation caches are loaded with `np.load(npz, allow_pickle=True)`, here and at `experiments/cv_bench/canaries.py:45`, so opening a crafted `.npz` runs arbitrary code. Confidence: high that a crafted cache executes code; low that one reaches these tools today, since current caches are generated locally.
  Attack vector: Both tools take the cache path from the command line (`replay_cache.py compose NPZ OUT`, `canaries.py OUT_DIR CACHE.npz ...`). The documented workflow (README.md:238, docs/cv-instruments.md:33-38) treats caches as data that both arms of an A/B replay. A cache from anyone else, for example one attached to an issue, copied between machines, or committed beside `word_crops.npz`, runs its payload when line 104 (or canaries.py:46) reads `z["words"]`, before any reforge code runs.   Evidence: replay_cache.py:93-94 writes `words=np.array(flat, dtype=object)`, :103-104 load it with `allow_pickle=True` and read `z["words"]`, and canaries.py:45-46 repeat the pattern. The committed `word_crops.npz` and `descender_baselines.npz` hold only uint8 arrays and load with the safe default (bench_readers.py:67, test_baseline.py:381).
  Remediation: Store the words as JSON text, for example `words_json=np.array(json.dumps(flat))`, read them back with `json.loads(str(z["words_json"]))`, and drop `allow_pickle=True` from both loaders.
